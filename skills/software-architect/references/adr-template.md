# ADR template

```markdown
# ADR-NNN: Title

- Status: proposed | accepted | superseded
- Date: YYYY-MM-DD
- Context: what forces the decision (scale, PDPL, ops, existing schema)
- Decision: what we will do
- Alternatives: what we rejected and why
- Consequences: migrations, APIs, queues, rollback
- Follow-ups: tickets / docs to update
```

Keep one decision per ADR. Link the code paths and the canonical business doc that the decision must not contradict.
